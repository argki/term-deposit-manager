# 定期預金管理アプリ 要件定義書

## 1. 背景と目的

### 1.1 現状の課題（As-Is）
複数銀行の定期預金を Excel シートで管理する場合、以下の課題が生じやすい。

1. **一覧性・視認性の低さ**
   - 左側に元の預入情報、右側に積替先の情報が横に並ぶ 2 ブロック構成になっており、現在有効な預金がどれで、合計いくら運用中なのか直感的に把握しにくい。
   - 銀行ごとに空白行や小計行が混在しているため、銀行を横断した「満期が近い順」「金利が低い順」などのソートや比較ができない。
2. **ステータス表現（背景色）の分かりにくさ**
   - 満期終了・積替済み（無効になった預金）の行を赤色などで目立たせる運用では、エラーや警告のように見えて「完了・無効（アーカイブ）」であることが直感的に伝わりにくい。
   - まもなく満期を迎える行を手作業で色分けして管理する運用では、日時の経過に応じた自動判定・見落とし防止ができない。
3. **トレース（履歴追跡）と積替判断のしにくさ**
   - 「いつ・どこに・どういう条件で預け入れて、どこへ積み替えたのか」の系譜（トレース）が表の左右配置に依存しており、複数回の積替や条件比較が追いにくい。
   - 「満期までの期間がまだ先（長期）なのに金利が低い預金」を抽出して積替候補として検討するための指標・フィルタがない。
4. **保守性・環境非汚染**
   - PC 本体に Node.js 等を直接インストールせず Docker コンテナ上で完結し、ダブルクリックで起動できるローカル Web アプリとして構築したい。

### 1.2 目的（To-Be）
- Excel 管理から脱却し、**扱いやすく見やすい新設計の UI を持つローカル Web アプリケーション**を構築する。
- 既存の Excel 書き出し CSV のデータを取り込めるようにし、初期移行コストを抑える。
- 以下の 3 つのコア体験を実現する：
  1. **満期アラートの自動把握**: まもなく満期を迎える預金を日付ベースで自動判定し、青系ハイライトと残り日数バッジで即座に把握できる。
  2. **積替検討の指標化**: 満期までが先で金利が低い預金をソート・ハイライトし、積替候補の検討に活用できる。
  3. **預入・積替トレースの可視化**: 元の預入から積替先までの履歴チェーンを紐づけて管理し、いつでも条件の経緯を追跡できる。
- 無効（満期終了・積替済）データは警告色（赤色）を使わず、**「無効・完了」と一目で分かる落ち着いたグレー系（ミュート表示）** に設計する。

## 2. 機能要件

### 2.1 ダッシュボード・サマリー表示
- **F-01: ポートフォリオ概要（KPI カード）**
  - **運用中残高合計**: 現在有効な定期預金の合計金額（円・カンマ区切り）を表示する（例：`10,000,000 円`）。
  - **加重平均金利**: 運用中残高に対する加重平均金利（`%`）を自動計算して表示する。
  - **まもなく満期**: 設定した日数以内（デフォルト 90 日以内、設定変更可）に満期を迎える預金の件数・合計金額を表示する。
  - **積替検討候補**: 残存期間が長く金利が低い預金（しきい値設定可）の件数・合計金額を表示する。
- **F-02: 銀行別サマリー・グラフ可視化**
  - 銀行ごとの運用中残高、構成比、銀行別平均金利を棒グラフやサマリーバーで可視化し、金融機関別の偏りを把握できること。
  - 満期年別（または四半期別）の満期到来予定金額の推移を可視化し、今後の資金流動予定を把握できること。
  - グラフのツールチップは視認性の高い単位・降順表示とし、銀行別グラフのバーをクリックすることで該当銀行の一覧フィルタへ連動できること。

### 2.2 ステータス設計と視覚的表現（Excel からの刷新）
- **F-03: 自動ステータス判定と直感的な配色**
  - 各定期預金レコードは以下の 4 ステータスを持ち、UI 上で明確に色分け・バッジ表示する。
    1. **運用中（`active`）**: 通常表示（クリーンな白背景＋緑系またはニュートラルバッジ）。
    2. **まもなく満期（`maturing_soon`）**: **青系ハイライト**（爽やかなスカイブルー系の背景ティント＋「あと ○○ 日」カウントダウンバッジ）。満期日までの残日数が設定しきい値（例：90 日以内）かつ未処理の場合に自動適用する。
    3. **満期終了（`matured`）**: **無効・完了を意味するグレー系**（落ち着いたスレート／グレー背景＋薄文字または取り消し線＋「満期終了」バッジ）。警告色（赤）は使わず、アーカイブ状態であることを明確化する。
    4. **積替済（`rolled_over`）**: **無効・アーカイブを意味するグレー系**（落ち着いたグレー背景＋「積替済」バッジ＋積替先へのリンク表示）。
  - **アーカイブ表示切替**: デフォルトでは「現在有効（運用中・まもなく満期）」を中心に表示し、トグルスイッチで「満期終了・積替済（無効分）」の表示／非表示をワンクリックで切り替えられること。

### 2.3 一覧表示・ソート・フィルタ・積替検討指標
- **F-04: 扱いやすい統合テーブル＆銀行別ビュー**
  - 「全銀行統合一覧」と「銀行別グループ表示（銀行ごとの小計付き）」を切り替えられること。
  - 以下の項目を見やすく整理して表示すること（元の Excel の「満期 年/月/日」3 列分割を 1 つの日付表示＋残り日数に統合）：
    - ステータス（バッジ）
    - 銀行名
    - 預入日（開始日・任意） / 満期日（`YYYY/MM/DD`＋残り日数）
    - 預入期間（年 / ヶ月）
    - 適用金利（基本金利 + キャンペーン上乗せがある場合は内訳も表示、例：`1.25% (1.00% + 0.25%)`）
    - 預入金額（円）
    - 満期利息（予定または実績）/ キャンペーン名・メモ
    - トレース（積替元／積替先の有無アイコン）
- **F-05: 実用的なソート・フィルタ・検索**
  - 以下のソート軸をワンクリックで切り替えられること：
    - 満期日が近い順 / 遠い順
    - 金利が低い順 / 高い順
    - 金額が大きい順 / 小さい順
    - 銀行名順
  - フィルタ機能：
    - 銀行による絞り込み（複数選択可）
    - ステータスによる絞り込み（すべて / 運用中のみ / まもなく満期のみ / 無効分のみ）
    - **「積替検討候補」クイックフィルタ**: 「残存期間 ○ 年以上（デフォルト：1 年以上）」かつ「適用金利 ○% 未満（デフォルト：1.0% 未満）」などの条件に一致する預金を抽出し、積替検討の指標としてハイライト表示できること（しきい値は画面上で調整可能）。

### 2.4 預入・積替トレース（系譜管理）と CRUD 操作
- **F-06: 定期預金の登録・編集・削除・Undo/Redo**
  - 新規預入の登録、既存預金の条件編集、削除ができること。
  - 預入日と期間（年または月）を入力した場合に満期日を自動計算する補助機能（手動上書きも可）を備えること。
  - 基本金利とキャンペーン上乗せ金利を入力すると合計適用金利を自動算出し、税引前／税引後の概算満期利息を参考表示すること。
  - **誤操作防止確認**: 削除時は対象預金（銀行名・満期日・金額）および積替チェーンへの影響を確認ダイアログに明示した上で実行し、削除後も Undo により復元できること。
  - **和暦の補助表示**: 西暦（`2027` 等）を内部基準としつつ、満期年や満期年別グラフ等で和暦（`R9` 等）を補助表示できるようにすること。
  - **キーボード操作性・IME 保護**: `Ctrl+Z` / `Ctrl+Y`（macOS は `Cmd+Z` / `Cmd+Shift+Z`）による Undo / Redo、および `Esc` キーでのモーダルクローズ等のキーボード操作に対応すること。また、日本語 IME 変換中（`isComposing`）の `Esc` / `Enter` で誤ってモーダルが閉じたり確定されたりしないよう保護すること。
- **F-07: 積替（ロールオーバー）処理とトレース表示**
  - 運用中またはまもなく満期の預金に対して「積替登録」アクションを実行できること。
  - 「積替登録」を実行すると、元の預金を自動的に `rolled_over`（積替済・無効）に更新し、元の預金 ID（`parentDepositId`）を紐づけた新しい預金レコード（金額等を引き継ぎ、新条件を入力）を作成できること。
  - 一覧のトレースアイコンや行詳細パネルから、**「元の預入 → 1回目の積替 → 現在の預入」といった履歴チェーン（いつ・どこに・どういう条件で預けていたか）** をタイムライン形式で辿れること。
  - 満期を迎えて単に解約・終了する場合は「満期終了にする」アクションで `matured` 状態へ変更でき、受取利息（実績）を記録できること。

### 2.5 データ移行（CSV インポート）と永続化・同期
- **F-08: Excel 書き出し CSV 形式のインポート機能**
  - 既存 Excel から出力された定期預金一覧 CSV をアップロードして一括登録できること。
  - CSV ファイル読み込み時は **UTF-8（厳密判定）と Shift-JIS を自動判別してデコード**し、Windows Excel から出力した Shift-JIS 形式でも文字化けせず取り込めること。
  - 以下の CSV 特有の構造を正確に解釈すること：
    - A 列の銀行名引き継ぎ（銀行名が空欄の行は直前の銀行に所属）。
    - 左ブロック（満期年・月・日、期間、金利、金額、満期利息、キャンペーン、合計金利）と右ブロック（積替先データ）の分離パース。
    - 銀行小計行・全体合計行・空行の自動スキップ。
    - 金額欄の前後空白・カンマ除去、および `"満期終了"` 文字列の検知（`matured` として登録し、満期利息列の値を実績受取額/利息として保持）。
    - 右ブロックが存在する行は、左ブロックを `rolled_over`（積替済・無効）として登録し、右ブロックを `parentDepositId` で左ブロックと紐づけた新規レコードとして登録すること（左右が同一内容の重複行がある場合は適切に重複統合または確認プレビュー表示を行う）。
    - キャンペーン列の記号・表記（例：`+0.25` 等の加算表記、テキスト形式のキャンペーン名、連続ドット等の表記ゆれ）の正規化。
    - インポート実行前にプレビュー（件数・銀行別集計・合計金額の確認）を表示し、既存データへの「上書き」または「追加」を選択できること。
- **F-09: ローカル永続化・JSON/CSV バックアップ・複数タブ同期**
  - ホスト側マウントディレクトリ（`./data/deposits.json`）へローカル保存し、外部送信を行わないこと。
  - ヘッダーに現在の保存状態を示すステータスバッジ（「ローカル保存済み」／保存処理中は「保存中...」）を表示すること。
  - JSON 形式での全データエクスポート／インポート（バックアップ・復元）および **UTF-8 BOM 付き CSV エクスポート**（Excel 等での二次確認・アーカイブ用途）ができること。
  - **複数ウィンドウ・タブ間のリアルタイム同期（SSE: `GET /api/events`）**:
    - 送信元識別子（`X-Client-Id`）により自己更新の不要な再描画を防止しつつ、他タブ・別ウィンドウでの変更を自動反映すること。
    - **画面表示状態の独立性**: フィルタ・ソート順・表示形式（統合／銀行別）・無効分表示トグル・折りたたみ状態はウィンドウごとに独立保持し、他ウィンドウの操作で勝手に切り替わらないこと。
    - **編集中の保護と自動再接続**: 他ウィンドウの更新受信時に登録・編集モーダルを開いて入力中である場合は入力内容を破棄・上書きせず保護すること。また、コンテナ再起動やスリープ復帰で接続が切れた場合は自動再接続し、最新データを再取得して同期を回復すること。

### 2.6 レイアウト・UI 操作性改善（狭幅ウィンドウ対応・初期折りたたみ）
- **F-10: 狭幅ウィンドウ向けレイアウト設計**
  - 画面分割時などウィンドウ幅が狭い環境（`1100px` 以下）で、一覧表の各列が狭まり折り返し表示になって見にくくなることを防ぐこと。
  - 狭幅ブレイクポイント（`1100px` 以下）に応じて、**コンパクトなカード型リスト表示への切り替え**（銀行・ステータス・満期日・金利・金額・操作ボタンが折り返し崩れなく整列する構成）を実装すること。
- **F-11: 「新規登録」ボタンの一覧表付近への配置**
  - 登録操作と反映先の対応関係を直感的にするため、「新規登録」ボタンをページ最上部ヘッダーから**定期預金一覧表の直上（ツールバー／一覧見出し付近）**へ配置すること。
- **F-12: サマリー・グラフ・管理メニュー（CSV 取込・設定）の初期折りたたみ表示**
  - **サマリー（KPI カード）およびグラフ**: 初期状態では折りたたみ状態とし、画面を開いてすぐに一覧表を確認・操作できるようにすること（クリックでいつでも展開可能）。
  - **CSV 取込・JSON バックアップ・設定**: 日常的には使用しない管理機能のため初期状態では折りたたみパネル等に格納し、必要時のみ展開して操作できること。

## 3. 非機能要件

### 3.1 技術スタック・開発方針
- **NFR-01: 統一アーキテクチャ**
  - **言語**: TypeScript (strict)
  - **フロントエンド**: React + Vite + Recharts + Lucide React
  - **バックエンド**: Hono (`@hono/node-server`)
  - **永続化**: ローカル JSON ファイル（`/app/data/deposits.json`、一時ファイル経由のアトミック書き込み）
  - **品質管理**: `tsc --noEmit`、ESLint、Prettier、Vitest（ドメインロジック・CSV パーサ・API の単体テスト必須）
- **NFR-02: コンテナ完結・環境非汚染**
  - Docker / Docker Compose（`node:26-alpine` 等、最新の Active LTS ベースイメージを確認して採用）でビルド・テスト・実行を完結させ、ホスト OS に Node.js 等をインストールしない。
  - ポートは `127.0.0.1:3457:3457`（または環境変数 `PORT` で設定可能）に限定してバインドする。
- **NFR-03: クロスプラットフォーム起動体験・PWA オフラインフォールバック**
  - Windows（`start.bat` / `stop.bat` / `update.bat`）および macOS（`start.command` / `stop.command` / `update.command`）向けのダブルクリック起動・停止・更新スクリプトを提供する。
  - Windows 環境ではコンテナ稼働中にバックグラウンドで WSL セッションを維持（keepalive ロック）し、WSL の自動スリープによってアプリサーバーが停止しないようにすること。
  - 起動直後に `public/starting.html` を最大化ウィンドウで表示し、予約アップデートフラグ（`data/.update-pending`）がある場合は `git pull --ff-only origin main`（安全条件充足時）およびコンテナ再ビルドを実行し、ヘルスチェック通過後にアプリ本体へ自動遷移すること。起動後にはイメージ作成日時（30日経過）および `origin/main` の更新確認を行い、必要に応じて次回起動時アップデート予約を行うこと。
  - PWA（`manifest.webmanifest`, `sw.js`, `offline.html`, `icon.png` / `icon.ico`）を備え、コンテナ停止中にブラウザ／PWA からアクセスした場合は「サーバー停止中」案内画面を表示し、起動後に自動再接続すること。
- **NFR-04: モジュール最新化・品質保証**
  - `pnpm` と `pnpm-lock.yaml`、`.github/dependabot.yml`、`.github/workflows/ci.yml` により依存パッケージ・Docker ベースイメージ・GitHub Actions を最新安定版に保ち、型チェック・Lint・単体テスト・ビルドをコンテナ内で検証できること。
- **NFR-05: 完全ローカル・セキュリティ**
  - 金融資産データを取り扱うため、外部ネットワークへの通信・テレメトリ送信は一切行わず、`127.0.0.1` に限定公開する。

## 4. 開発ステップ方針
ステップ分割されたタスクリストに従い、ドメインロジック・ローカル API・UI・コンテナ環境の順に段階的に開発・検証を進める。
